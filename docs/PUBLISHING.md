# Publishing Foundations-Bench

The site is deliberately static: `preview.html` and `index.html` are generated by
`scripts/build_preview.py`, and `.nojekyll` keeps GitHub Pages from running Jekyll.
The generator also writes `docs/preview.html`, `docs/index.html`, and `docs/.nojekyll`
so both the root path and the `/docs/` path resolve. There is no Pages workflow.
Deployment uses the simple branch method so there is only one source of truth.

## One-time setup

1. Authenticate the GitHub CLI:

   ```bash
   gh auth login
   gh auth status
   ```

2. Initialize the local repository and make the first commit:

   ```bash
   git init -b main
   git add .
   git commit -m "Initial public release"
   ```

3. Create the public repository and push. Replace `OWNER` and `REPO`:

   ```bash
   gh repo create OWNER/REPO --public --source=. --remote=origin --push
   ```

4. In the repository, open **Settings → Pages**:
   - **Source:** Deploy from a branch
   - **Branch:** `main`
   - **Folder:** `/ (root)`
   - **Save**

5. Wait for the Pages deployment, then check all three entry paths:

   ```bash
   BASE="https://OWNER.github.io/REPO"
   for p in "" "preview.html" "docs/preview.html"; do
     printf "/%s -> " "$p"
     curl -s -o /dev/null -w "%{http_code}\n" "$BASE/$p"
   done
   ```

   With **Folder: `/ (root)`** the expected result is `200`, `200`, `200`.
   If `/docs/preview.html` is `404`, either the mirror was not regenerated or
   Pages is still serving an older build. Keep the source at `/`; the `docs/`
   mirror exists so the `/docs/` URL also works without changing the source.

6. Regenerate the site and README so every link uses the published URL. The
   generators read `origin` automatically:

   ```bash
   python scripts/make_report.py
   python scripts/build_preview.py
   git add README.md preview.html index.html docs/preview.html docs/index.html \
     docs/.nojekyll results/report.md results/headline.json paper/figures
   git commit -m "docs: point at the published Pages URL"
   git push
   ```

   If the remote cannot be detected, set the URLs explicitly:

   ```bash
   REPO_URL=https://github.com/OWNER/REPO \
   PAGES_URL=https://OWNER.github.io/REPO \
   python scripts/make_report.py
   PREVIEW_REPO_URL=https://github.com/OWNER/REPO python scripts/build_preview.py
   ```

## Verify

```bash
python scripts/check_results.py
python -m pytest -q
ruff check .
ruff format --check .
```

Open the Pages URL and check:

- the hero animation and the four 3D cards;
- the **Results** tabs E1–E6;
- the **Learn** progress bar and all ten steps;
- the **Quiz**: answer one question, check it, and advance;
- the **Business** section and the reproduction commands;
- the mobile layout and the **Print / save PDF** button.

`scripts/check_results.py` also verifies that `preview.html` and `index.html` are
byte-identical, that the README has no unresolved placeholders or tool mentions,
and that the GIF, screenshots, `.nojekyll`, and `CITATION.cff` are present.

## Repository metadata

Set a short description:

> Six pre-registered studies on the foundations of AI. Every number executed,
> hashed, and reproducible.

Add topics: `reproducibility`, `benchmark`, `pre-registration`, `autograd`,
`transformers`, `attention`, `statistics`, `machine-learning`, `open-science`.

Upload `docs/assets/preview-hero.png` as the social preview image.

## Refreshing the demo assets

Maintainers only. The recorder needs Playwright and ffmpeg:

```bash
python -m pip install playwright
python -m playwright install chromium
python scripts/make_demo.py
```

The script writes six screenshots plus `docs/assets/demo.gif` and
`docs/assets/demo.mp4`. The GIF is capped below 6 MB by the generator; if the
tour changes materially, check the file size and the first frame before
committing.
